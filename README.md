# Perch Bridge for PI

在 PI 模型列表中使用自己 Perch 套餐内的模型。无需事先安装 Perch CLI、Node.js 或 npm。

**v0.3.1 是 ACP 桥接版本，运行 PI 外层 Agent 和 Perch 内层 Agent；不是纯模型 API 接入。** PI 负责上下文和实际工具执行，Perch 的系统指令、Agent 与 Skill 机制仍可能参与模型响应。

## 安装与登录

1. 在 PI 的插件管理中安装 `dist/local.pi-perch-0.3.1.piplug`，或以开发插件方式选择本项目的 `plugin` 文件夹。
2. 打开 **Perch Bridge** 面板。首次启动会从 npm 官方源下载运行组件；下载失败时点击“准备组件”重试。
3. 选择 Google / GitHub，点击“登录 Perch”，在浏览器完成登录。已有 Perch 登录会自动识别。
4. 在 PI 模型选择器中选择 **Perch** 下的模型。面板中的“测试连接”可检查当前连接。

PI 0.21.0 的内置 Node 运行环境负责启动组件。安装只写入插件自己的数据目录，不添加全局命令、不修改 PATH、不要求管理员权限。插件安装包不包含 Perch 的专有程序；首次使用自动从官方 npm 源安装 `perchai-cli@2.4.120`，并使用隔离的 npm 安装器（10.9.4），安装脚本禁用。

## 工作方式

已在 Windows PI-Desktop 0.21.0 验证。

PI → 本机回环接口 → 插件托管的官方 `perch acp` → Perch。

官方 CLI 负责认证、刷新登录和模型执行。插件不会直接调用私有 `model-call` 接口。登录使用官方 `~/.perch/cli-auth-session.json`；与已安装的官方 CLI 共享登录，不保存第二套刷新令牌，也不把凭据打包。

每次调用使用独立的模型/思考配置，不修改用户平时的 CLI 设置。模型列表随账号套餐刷新，未开放的模型不能使用。

## 额度与模型映射

- 分别显示手动选模、公平使用的 5H / 7D 用量、剩余比例和下次额度释放时间。这是滚动窗口，不是全部额度同时清零。
- 从账号的当前订阅周期起止时间分页读取官方用量账本，按模型记录汇总调用次数、输入/输出/缓存/总 Token、折算用量 pt。包含其他 Perch 客户端、历史模型和内部调用，不局限于此插件。若记录未取全会明确标注。
- 无法取得套餐起止时间时不改用自然月冒充套餐周期。接口未返回的额度不会显示成零。
- Token 用量统一显示为 M（1M＝100 万），悬停可查看精确值；调用次数和用量 pt 保留原单位。
- 每个模型可手动勾选是否映射到 PI，支持全选/全不选。点击“保存映射”后保存到插件数据目录，重启、更新和刷新模型目录不会丢失选择。全部取消时会移除 Perch 的模型提供商声明。
- 直接读取 PI 模型列表核验注册状态。保存后若显示“待同步”，在 PI 插件管理中**关闭后重新启用**本插件，或重启 PI。PI 0.21.0 的“重载”按钮只更新插件进程，不会更新已注册的模型列表。当前会话的模型仍在 PI 自带选择器切换，面板不会主动更改它。
- 额度每分钟刷新，逐模型明细每五分钟刷新，也可以点击各区的刷新按钮。刷新账本不调用模型。

## 当前边界

- 这是官方 CLI 桥接，不是原始模型 API。Perch 自身的系统指令、上下文处理、套餐额度仍然生效。
- 普通回复支持 ACP 流式输出。带工具的回复先解析模型生成的 JSON，再交由 PI 执行工具；这部分会在完整回复后出现，兼容程度取决于模型。
- 模型请求串行执行，启动 CLI 会增加首字延迟。
- 思考档位会传给 CLI。`temperature`、`max_tokens` 等原始 API 参数不能保证由 CLI 精确执行；ACP 未报告的 token 用量不伪造。
- 图片使用 PI 附件中的内嵌图片。仅提供远程图片 URL 的消息暂不支持。

## 开发验证

真实模型测试最多选择 1–2 个模型，仅使用 DeepSeek / GPT，不做全模型遍历；详见 `AGENTS.md`。

`node --test tests/regression.js`：工具协议、图片消息、流结束/错误、认证回归。

`tests/standalone.cjs`：使用 PI 自带 Node、清理 PATH 后调用插件私有组件，验证无全局 CLI 的真实回复。

测试不会改写源码或已安装插件的模型端口。生产服务固定绑定 `127.0.0.1:41891`；端口冲突会明确报错。
